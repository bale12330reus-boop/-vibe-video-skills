# 知识科普视频：输入主题 → 成片

这套流程蒸馏自「曼德拉效应」一条成片（2 分 28 秒，用户满意）。`examples/曼德拉效应/` 里有它每一步的真实产出，拿不准格式时照着看。

## 你从用户那里拿什么

- **必填**：主题，比如"幸存者偏差""为什么天空是蓝的"。
- **可选**（不说就用默认）：时长（默认跟 BGM 走，约 2–2.5 分钟）、横屏/竖屏（默认横屏 1920×1080）、风格（默认 `references/风格-博物馆纪录片.md`）、是否分步确认（默认不分步）。
- **BGM**：在项目文件夹（或用户说的位置）找音频文件（mp3/wav/m4a/flac）。找到就复制成 `<主题>/bgm.mp3`；有多个就问用哪个；**一个都没有就停下来问用户要**。不要自己生成或下载音乐（有版权风险）。

## 两种模式

- **全自动（默认）**：一口气做到成片，中间不停。每一步做完先按该步的 `<check>` 自查，自查不过就自己改，改好再往下走。
- **分步**（用户说"每步停一下""我要确认"）：在 文章 → 文案 → 样图 → 分镜 → 10 秒样片 这 5 处各停一次，等用户点头。

无论哪种模式，只在这些情况停下来问用户：没有 BGM；环境装不上；用户本人才能做的事（比如截一张只能手动截的图，用户不截就改成文字动画，不要卡住）。

## 文件夹

```
<项目根>/<主题>/
  bgm.mp3
  文章.md  文案.md  找图.md  分镜.md  投稿文案.md
  素材/                 下载或截来的原图，文件名以幕号开头：03-xxx.jpg
  samples/             样图
  video/
    index.html         由 assets/index-模板.html 改出来
    assets/  gsap.min.js  grain.png  bgm.mp3  fonts/  img/（素材复制进来）
    renders/           成片
```

## 提示词写法

每一步都用 4 个标签写给自己：`<role>` 扮演谁、`<task>` 做什么、`<avoid>` 不要做什么、`<check>` 做完先自查什么。下面每一步给的就是蒸馏后的提示词，【主题】换成用户的主题。

## 第 0 步 · 环境（第一次用时）

需要：Node.js 20 以上、FFmpeg（含 ffprobe）、HyperFrames、Python 3（numpy + miniaudio）、一个 Chromium 内核浏览器、思源宋体。详细装法和省内存的办法见文末「环境」。先检查已经装了什么，只装缺的。

## 第 1 步 · 搜集 → 文章.md

```
<role>你是知识科普作者，最在意事实准确。</role>
<task>围绕【主题】上网查，挑 8 到 10 个关键节点（讲原理的题目就讲成 5 到 8 个单知识点）。每个写清哪一年、谁、做了什么、为什么重要，按时间排，整理成 文章.md。文末加两小节：「能做反转的点」（大众以为 vs 真相，或资料本身互相矛盾的地方）、「落到普通人身上的结尾」。</task>
<check>年份、人名、数字、原话都要有出处，链接写在每段后面。优先：百科、原始论文、大学或机构官网、权威媒体、事实核查网站。只在博客、教辅、内容农场见过的说法删掉，或者改成不带具体数字的说法。看着像、其实不属于这个主题的例子也删掉。删了什么、为什么删，列在文末「自查删除」。</check>
```

## 第 2 步 · 编排 → 文案.md

```
<role>你是无旁白知识短视频的编剧，擅长把复杂的事讲给完全不懂的人听。</role>
<context>横屏视频，约 2 分钟（最终长度跟 BGM 走），没有旁白，观众只看屏幕上的字配音乐，所以每句话都要短、一看就懂。</context>
<task>把 文章.md 改成 文案.md，分 6 到 8 幕，每一行 = 一屏字，全片约 50 到 60 屏。第 1 幕第一屏先抛一个观众会忍不住先在心里答的问题（例：「考你一个问题」+ 问题本身），第 1 秒内就要亮出；中间贴着事实走，至少用一个生活里的比方，安排一次反转；结尾落到普通人身上，最后一屏引导评论（「你还……过什么？评论区说说」）。每幕后面标（节点 N），对应 文章.md 的第几个节点。</task>
<avoid>专业术语不解释；一屏超过 20 个字；文章.md 里没有的事实；套话（「你知道吗」「让我们一起」「震惊」）。</avoid>
<check>逐屏数字数，超过 20 个字的拆开；每个事实都能对回某个节点；从头读一遍，不像人话的改成口语。</check>
```

## 第 3 步 · 找图 → 找图.md + 素材/

```
<context>视频不能只有字，每一幕最好有一张真实的图（老照片、人物肖像、实验现场、实物、地点），之后会统一处理成视频的风格。</context>
<task>按 文案.md 一幕一幕列出 找图.md：用在第几幕、画面是什么、来源网址、作者、许可。能下载的自己下载，存进 素材/，文件名以幕号开头。只能截网页的，写清网址和截哪一块交给用户；用户不截，就把那一处改成文字或图形动画。文末写一段「图片署名」，投稿时可以直接贴进简介。</task>
<avoid>标注版权所有、来路不明的图；有版权的角色、电影剧照、书封、商标——这些在第 4 步改用抽象图形表现（画一个道具再打叉、把台词里的名字划掉、字母变形），不要画角色本人。</avoid>
<check>每张图的许可都允许再使用（公有领域 / CC0 / CC BY / CC BY-SA），BY 类都写了署名；图片清晰度至少 1280 像素宽。</check>
```

下载图的办法：首选 Wikimedia Commons。用 API 同时拿到图片地址和许可：
`https://commons.wikimedia.org/w/api.php?action=query&format=json&prop=imageinfo&iiprop=url|extmetadata&iiurlwidth=1920&titles=File:<文件名>`
（`extmetadata` 里的 `LicenseShortName`、`Artist` 就是许可和作者）。请求时带上一个 User-Agent 头，否则可能被拒。

## 第 4 步 · 定样式 + 写分镜 → samples/ + 分镜.md

### 4a 定样式

- **默认**：直接用 `references/风格-博物馆纪录片.md`。做 2 张 1920×1080 样图检查效果：第 1 幕第一屏、一张带照片的屏。
- **用户给了自己的风格描述**：保留它的整体感觉，把描述里属于别的主题的道具换成和【主题】有关的东西，交付时说明换了什么。
- **分步模式且用户想挑**：出 3 个差别大的风格各一张样图，各说一句为什么适合，等用户选。

```
<avoid>深色背景配霓虹光；紫色渐变；字都堆在正中间；所有东西都淡入淡出；卡通手绘；粗黑描边；扁平大色块；像 PPT 一样规整的排版。</avoid>
```

用户后来说不喜欢的东西，随时加进 `<avoid>`，后面每一步都避开。

样图做法（轻、不占内存）：写一个 1920×1080 的 HTML 页面，用无头浏览器截图：
`"<浏览器路径>" --headless=new --disable-gpu --hide-scrollbars --window-size=1920,1080 --screenshot="<输出.png>" "file:///<样图.html>"`
截完自己打开 PNG 看一遍：字有没有出框、重叠、太小。

### 4b 写分镜

先读 BGM 的节拍：`python scripts/beat.py <主题>/bgm.mp3`，得到 BPM、第一重拍（`first_downbeat`）、每小节起点（`bar_starts`）、每 2 秒响度（`loud_2s_db`）。

```
<role>你是动效导演，最在意节奏。</role>
<task>用选定的风格写 分镜.md。开头写「全片统一规则」：底色、配色、字体字号、两种版式、动作词表、不要做清单（照 references/风格-博物馆纪录片.md）。然后一张表：镜号 | 时间（秒） | 主体（画面中央） | 左上 / 右上 | 字 | 动作。截图要处理成这个风格的样子，不要直接贴上去。镜头切换卡在拍子上。写完先自查。</task>
<rules>
- 一屏字 = 一小节（BPM 100–120 时约 2 秒）；两行字或超过 14 个字的给 2 小节。每次切换都落在小节第一拍。
- 响度相邻两格突然升高 6 dB 以上的地方是「爆点」。第一个爆点放开头问题的答案（例：「错。」砸下来 + 书框亮一下 + 画面轻颤）；前奏太长就加倒计时或铺垫镜头填满，让答案正好落在爆点上。另一个爆点放全片最重的一下。
- 讲原理的段落放在音乐安静的那一段。
- 总长：最后一屏落在音乐自然结束的地方，最后 0.5 秒淡出到全黑。
- 每个镜头写清用 素材/ 里哪张图；有版权的东西写成抽象道具。
- 每一幕左上写「年份 · 地点 · 人物」，右上写出处标题 + 一句核对过出处的原文引用。
- 最后一屏底部小字：「图片出处见简介 · 内容由 AI 生成」。
</rules>
<specs>横屏 1920×1080，每秒 30 帧（竖屏 1080×1920）。</specs>
<check>文案里的每一屏都在分镜里（逐条对照，写出对照结果）；年份、数字和 文章.md 一致；没有一屏停留短于 1.8 秒；和文案相比新加或改动的字，单独列出来告诉用户，并同步改进 文案.md。</check>
```

## 第 5 步 · 检查分镜

分步模式：停下来让用户看 分镜.md。全自动模式：自己按这几条再过一遍——第一屏 1 秒内亮出问题；爆点落在音乐变强的那一拍；没有一段连续 3 屏以上画面不变；没有用到有版权的形象；总长和 BGM 对得上。

## 第 6 步 · 直出：先 10 秒，再整片

```
<task>照分镜做。先只做开头 10 秒左右（取到某一小节的结束处），渲成 MP4 自查，满意了再做整片。</task>
<check>做完抽帧看：字有没有出框、重叠、太小；年份和文案对不对；该消失的东西有没有留到下一屏；切换在不在拍子上。有问题改完再交付。</check>
```

具体做法：

1. 把 `assets/index-模板.html` 复制成 `video/index.html`，把 `assets/gsap.min.js`、`assets/grain.png`、`bgm.mp3`、字体、素材图复制进 `video/assets/`。按模板里标【改】的 4 处填：总时长、每幕的 section、B0/BPM/END、每一幕的代码。时间一律用 `bar(k)` / `beat(k, n)` 写。完整写法参考 `examples/曼德拉效应/index.html`。
2. **整片渲染前先截关键帧**：在每个镜头的中间时刻各截一张（曼德拉效应截了 46 张）：
   `npx hyperframes snapshot video --at 3.2,8.6,14.0,... -o video/snapshots`
   逐张打开看，按文末「踩过的坑」逐条查。
3. **10 秒样片**：临时把 `#root` 和 `#bgm` 的 `data-duration` 改成某一小节结束的秒数（例如 10.82），渲染：
   `npx hyperframes render video -o video/renders/sample-10s.mp4`
   渲完改回总时长。用 ffprobe 确认分辨率、帧率、时长、有声音；抽 8–10 帧看。
4. **整片**：`npx hyperframes render video -o video/renders/<主题>-full.mp4`
   内存紧张（可用内存不到 4 GB）时加 `--workers 1 --low-memory-mode`。
5. 成片再抽 12 帧检查，用 ffprobe 确认时长、帧数、声音。
6. 文件太大不方便发（比如超过 50 MB）就另压一个预览版，原版不动：
   `ffmpeg -i <full.mp4> -vf scale=1280:-2 -c:v libx264 -crf 28 -preset slow -c:a aac -b:a 128k <full-preview.mp4>`
7. 交付时说清楚：你看不到声音，卡没卡准拍子要用户戴耳机听一遍。

## 第 7 步 · 投稿文案 → 投稿文案.md

- 标题 3 个备选，都以「Vibe知识大赏｜」开头，推荐一个（最好和视频第一屏的问题一样）。
- 话题：#vibe知识大赏 + 3–4 个主题词。
- 简介四块：开头两句钩子；【内容由 AI 生成】；【资料出处】（文章.md 里的来源）；【图片署名】（找图.md 末尾那段）。
- 配乐一栏留给用户填歌名和作者，并提醒：有版权的音乐可能被平台检测。
- 活动要求：标题以「Vibe知识大赏」开头、带 #vibe知识大赏、简介写出处和图片署名、声明「内容由 AI 生成」、在截止日期前发。

## 第 8 步 · 封面 → cover/cover-16x9.png + cover/cover-3x4.png

**全系列统一格式，不要每期重新设计。** 把 `assets/cover-模板.html` 复制成 `<主题>/cover/cover.html`，只改开头 `COVER` 里的字段：
- `no`：第几期（两位数，曼德拉效应 01、幸存者偏差 02，往后顺延）
- `topic` / `topicEn`：主题中文名 / 英文大写
- `kick` + `title`：用视频第一屏的问题。`title` 不超过 8 个字，用 `<span class='r'>…</span>` 只标红一个词
- `sub`：副标题，不超过 16 个字（一般是问题的前提）
- `img` / `imgPos` / `cap` / `year`：从 素材/ 里挑一张冲击力最强的真实照片，写图注和罗马数字年份
- `seal`：火漆封印上的 2 个字（例：考题、反转、真相）

固定不变：深黑棕底 + 双层金框 + 四角菱形、左上「VIBE 知识大赏 No. xx」、主题名金色、大标题象牙白配一个暗红词、馆藏图版、火漆封印、角落 #vibe知识大赏。横版左文右图，竖版上图下文。

出图（和样图一样用无头浏览器截图，很轻）：
```
"<浏览器路径>" --headless=new --disable-gpu --hide-scrollbars --virtual-time-budget=4000 --window-size=1920,1080 --screenshot="<主题>/cover/cover-16x9.png" "file:///<主题>/cover/cover.html"
"<浏览器路径>" --headless=new --disable-gpu --hide-scrollbars --virtual-time-budget=4000 --window-size=1080,1440 --screenshot="<主题>/cover/cover-3x4.png" "file:///<主题>/cover/cover.html?r=3x4"
```
`--virtual-time-budget` 是为了等字体加载完再截图。截完打开看：大标题有没有压到图版、字有没有出框。横版用于 B 站 / 抖音横屏，竖版用于抖音 / 小红书的 3:4 封面。

## 踩过的坑（曼德拉效应实测，逐条查）

- **第一屏太慢**：第二行字 1.2 秒才出来，没做到"1 秒内亮出问题"。主句和第二行都要在 1 秒内出现。
- **3D 翻面成镜像**：卡片翻面后显示的是正面的镜像。正反两面都要 `backface-visibility: hidden`，背面加 `transform: rotateY(180deg)`。
- **封印被挡住**：火漆封印被纸条盖住了。盖章类元素 `z-index` 设高（模板里是 90）。
- **东西留到下一屏**：封印在下一屏还没消失。每个元素都要在它镜头结束时 `hideAt`（模板函数大多带 `t1` 参数，别漏传）。还有一种更隐蔽的：**入场动画还没播完就到了 `hideAt` 的时间，动画会把元素重新显示出来**（幸存者偏差那条里，最后两张彩票卡一直留到下一幕）。批量入场时，让最后一个的入场在镜头结束前就播完。截关键帧发现不了这个问题，要从渲好的视频里抽镜头交界处的帧来查。
- **细线太淡**：裂纹在颗粒和暗角下几乎看不见。细线至少 2px、不透明度 0.8 以上。
- **渲染不确定**：不能用 `Math.random()`、`Date.now()`；用模板里带种子的 `rnd()`。所有动画放进一条暂停的 GSAP 时间轴，并注册 `window.__timelines.main`。
- **渲染时走网络会失败**：GSAP、字体、图片全部用本地文件，不要用 CDN 或网络字体。
- **中文路径**：miniaudio 直接打开中文路径会失败，`beat.py` 已改成先读字节。其他工具遇到中文路径出错，先复制到英文路径再处理。
- **编造引用**：右上角的原文引用必须能在 文章.md 的来源里找到原句；资料是英文就用英文，不要为了"古典感"编拉丁文。
- **版权形象**：皮卡丘、大富翁老头、星战角色、书封都没画，改成色块标本卡、细线单片眼镜打叉、台词划掉、字母 a 翻成 e。

## 环境

先查已经有什么（`node -v`、`ffmpeg -version`、`python --version`），只装缺的。下载安装包后核对官方校验码。

- **装在哪**：Windows 用户如果在意 C 盘空间，把工具装到别的盘（例：`F:\nodejs`、`F:\video-tools`），并把 npm 的全局目录和缓存也改过去：
  `npm config set prefix F:\nodejs\npm-global`、`npm config set cache F:\nodejs\npm-cache`
- **Node.js**：装长期支持版（LTS，20 以上）。
- **FFmpeg**：Windows 下载官方推荐的静态版本，解压后把 `bin` 加进 PATH。
- **HyperFrames**：在工具目录里 `npm install hyperframes@0.8.143 gsap@3.14.2`，用 `npx hyperframes ...` 调用（在工具目录里运行，或用 `npx --prefix <工具目录>`）。关掉匿名使用数据上报：`npx hyperframes telemetry disable`（或设环境变量 `HYPERFRAMES_NO_TELEMETRY=1`）。`assets/gsap.min.js` 就是 `node_modules/gsap/dist/gsap.min.js`。
- **浏览器**：HyperFrames 要一个 Chromium 内核浏览器。没装 Chrome 的 Windows 电脑可以直接用自带的 Edge：
  `$env:HYPERFRAMES_BROWSER_PATH = "C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe"`
- **Python**：建一个虚拟环境，`pip install numpy miniaudio`，用来跑 `scripts/beat.py`。
- **字体**：思源宋体（Noto Serif SC）和思源黑体（Noto Sans SC）的可变字体，放进 `video/assets/fonts/NotoSerifSC-VF.ttf`、`NotoSansSC-VF.ttf`（模板两个都声明了，缺一个渲染时会报 "Fonts FAILED"，不影响画面但要补上）。先看系统字体文件夹里有没有，没有就从 Google Fonts 或 GitHub 的 notofonts/noto-cjk 下载。英文用系统自带的 Palatino Linotype（Mac/Linux 没有就换 EB Garamond）。
- **内存**：每个渲染进程约 256 MB。可用内存紧张时用 `--workers 1 --low-memory-mode`，并且先做不吃内存的步骤（查资料、写文字）。参考速度：10 秒样片约 40 秒，2 分半整片约 8–10 分钟（单进程低内存模式）。
- **临时文件**：渲染的临时目录也可以指到非系统盘（设 `TEMP`/`TMP` 到例如 `F:\video-tools\tmp`）。
